## 并发与恢复证据

以下检查使用临时 SQLite 文件和受控 HTTP Transport，不消耗厂商额度。测试通过真实网关 handler、管理员配置与对账入口。例中的金额单位是十亿分之一元。

| 情况 | 可重复验证的结果 |
|---|---|
| 5 个请求争用 200 单位余额 | 单次预留 200，只有 1 个进入上游，另 4 个返回 402。独立 Key 同时进入上游。 |
| 并发或 RPM 为 1 | 在对应窗口拒绝多余请求并返回 429；并发请求结束后可再次使用名额。 |
| 5 个请求均获准 | 5 个均可同时在途。每笔实际费用 72，最终合计 360，预留归零。期间修改别名映射，已有请求仍按原渠道结算，下一请求走新渠道。 |
| 失败与不确定用量 | 本地校验失败记零。超时、取消、缺失用量与无最终用量的断流进入待核实。在断流或 HTTP 500 中收到可信用量时仍可结算。 |
| 异常退出 | 测试子进程在预留提交后直接退出，另一进程打开同一文件，保留全部 200 单位占用。通过核实入口结算 43 并释放占用。 |
| 重复通知 / 重复提交 | 重复核实返回 409；相同 Playground 请求 ID 只触发一次上游调用。 |
| 缺少可信上界 | 有限额度返回 422；无限额度继续转发并记录实测用量。 |
| 媒体恢复 | 持久化的 17 位厂商任务 ID 精确保留，重启后只查询既有任务；对成品 CDN 的下载请求不附带上游 API 凭证。 |

已通过 `go test -race -count=3 ./...`、`go vet ./...`、React 静态未定义变量检查及生产构建。交付源码、文档和编译产物已逐项扫描，未匹配到附件中的四个真实凭证。
